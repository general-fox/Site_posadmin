# Posadmin

Сайт автоматизации и сопровождения предприятий HoReCa: тарифы, предварительный калькулятор проекта, обратный звонок и заявки. Стек: Next.js 15, React 19, TypeScript. Серверная версия также содержит PDF-расчёт и защищённую админку прайса.

## Запустить на своём компьютере

Нужны **Node.js 24.15.0 или новее в ветке 24** (не 25) и npm. Для установки зависимостей и загрузки шрифтов при первой компиляции/сборке требуется интернет: сейчас Inter и Montserrat подключены через `next/font/google`.

**Самый простой способ на Windows:** установите [Node.js 24 LTS](https://nodejs.org/en/download), распакуйте архив целиком и дважды нажмите `START-WINDOWS.cmd` в папке `posadmin`. Он установит зависимости и запустит сайт. После сообщения `Ready` откройте [http://127.0.0.1:3000](http://127.0.0.1:3000), не закрывая окно запуска. При каждом запуске файл заново проверяет установку зависимостей; исходники и локальные данные не удаляются.

Ручной запуск на любой системе:

1. Распакуйте архив в отдельную папку или клонируйте репозиторий.
2. Откройте терминал в папке, где лежат `package.json` и этот README.
3. Выполните:

```sh
node --version
npm ci
npm run dev -- --hostname 127.0.0.1 --port 3000
```

После сообщения `Ready` откройте [http://127.0.0.1:3000](http://127.0.0.1:3000). Пока смотрите сайт, оставляйте терминал открытым; остановка — `Ctrl+C`. Команды одинаковы для Windows, macOS и Linux. Если PowerShell блокирует `npm.ps1`, используйте `npm.cmd` вместо `npm` — менять политику безопасности не нужно.

**Для просмотра файл `.env` и Telegram-бот не нужны.** Страницы и калькуляторы открываются с исходным прайсом из кода. Без настройки Telegram формы не доставляют заявки и показывают ошибку, а не выдают фиктивный успех. В локальной разработке приложение может создать собственную папку `private-data` с SQLite-базой; данные исходного компьютера в архив не входят.

Если порт 3000 занят, остановите другой экземпляр сайта или замените `--port 3000` на `--port 3001` и откройте соответствующий адрес. Сайт доступен только на вашем компьютере: указанный `127.0.0.1` не открывает его для локальной сети.

## Проверить production-сборку локально

После `npm ci`:

```sh
npm run build
npm run start -- --hostname 127.0.0.1 --port 3000
```

Перед запуском освободите этот порт. Сборка сохраняется в `.next-build`, режим разработки использует `.next`. После изменения исходников production-версию нужно пересобрать. Эти команды запускают сервер на компьютере, но не публикуют сайт в интернете. Для полноценного хостинга нужен Node.js-сервер; загрузки файлов на обычный статический хостинг недостаточно.

## Подключить отправку заявок — необязательно

Список настроек находится в [`.env.example`](.env.example). Когда будете подключать интеграции, создайте собственный `.env.local` в корне проекта и внесите **реальные значения** нужных переменных. Пустой пример не включает доставку. После изменений перезапустите сервер.

| Переменные | Назначение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_CHAT_ID` | Токен бота и чат для заявок на проект; также адресат обратных звонков до подключения сервисных тем. |
| `TELEGRAM_SERVICE_CHAT_ID`, `TELEGRAM_MANAGER_TOPIC_ID`, `TELEGRAM_RKEEPER_TOPIC_ID` | Необязательная маршрутизация обратных звонков в темы менеджера и технической команды. При настроенном сервисном чате отсутствие нужной темы блокирует отправку, а не перенаправляет заявку. |
| `GOOGLE_SITE_VERIFICATION`, `YANDEX_SITE_VERIFICATION` | Необязательные коды подтверждения сайта для поисковых систем; задаются перед сборкой. |
| `ADMIN_EMAIL`, `ADMIN_ORIGIN`, `ADMIN_ENCRYPTION_KEY`, `ADMIN_BOOTSTRAP_TOKEN`, `POSADMIN_DATA_DIR` | Только для настройки владельца и защищённой админки; для просмотра не требуются. |

Подробности маршрутизации и совместимости: [docs/callback-routing.md](docs/callback-routing.md). После подключения настоящего токена отправка из локального сайта тоже становится настоящей — проверяйте её только согласованной тестовой заявкой. Каталог `bot/` — отдельное приложение; запускать его для просмотра сайта или работы HTTP-отправки заявок не нужно.

Никогда не добавляйте `.env.local`, токены, базу, ссылку первичной настройки или резервные коды в публичный GitHub и передаваемый архив. В клиентские переменные с префиксом `NEXT_PUBLIC_` секреты помещать нельзя.

## Админка прайса — только если нужна

Для обычного просмотра этот шаг пропустите. Полный порядок настройки: [docs/admin-pricing.md](docs/admin-pricing.md).

Для собственной локальной админки сначала задайте свой `ADMIN_EMAIL` и точный `ADMIN_ORIGIN` в `.env.local`, например `http://127.0.0.1:3000`, затем выполните `npm run admin:prepare`. Без явно заданного origin команда использует `http://localhost:3000` — адрес браузера должен совпадать с настройкой. Команда создаёт локальные ключи и приватную ссылку, но не аккаунт: пароль и Authenticator настраиваются вами в браузере. После настройки сохраните резервные коды, удалите первичный ключ/ссылку по инструкции и перезапустите сайт.

Перенос существующей админки и изменённых цен — отдельная защищённая операция с базой и ключами. Передаваемый архив не содержит этих данных. На production необходимы HTTPS, постоянный каталог данных и один экземпляр сервера; подробности в инструкции выше.

## Демо без сервера

Есть отдельная статическая review-версия для GitHub Pages: [docs/review-demo.md](docs/review-demo.md). Она показывает интерфейс и калькуляторы, но **не отправляет заявки**, не создаёт PDF и не содержит админку/API. Публикация исходников в GitHub сама по себе не запускает серверные функции.

Для отдельной статической сборки из Git-клона после `npm ci` используется `node scripts/build-review-demo.mjs`. Ему нужны Git и репозиторий: ZIP без `.git` для этой команды недостаточен. Сборка имеет префикс `/Site_posadmin` и предназначена для HTTP-хостинга, а не открытия HTML двойным щелчком. Не включайте `NEXT_PUBLIC_REVIEW_DEMO=true` для полноценной серверной версии.

## Что передаётся

Архив исходников содержит код, публичные изображения и шрифты, конфигурацию, lock-файл зависимостей, примеры окружения и документацию. В нём нет `.git`, `node_modules`, `.next`, `.next-build`, готовой сборки, действующих `.env` и приватных данных. Зависимости устанавливаются на целевом компьютере через `npm ci`; аккаунт владельца, история и изменённый в админке прайс не копируются. После запуска новые локальные файлы будут принадлежать уже этому компьютеру.

Чтобы подготовить новый архив из Git-клона, сохраните нужные изменения коммитом и выполните `node scripts/create-handoff.mjs`. ZIP появится в `output/`. Скрипт берёт только зафиксированные файлы, проверяет отсутствие распространённых приватных файлов и не перезаписывает существующий архив. Это не заменяет проверку содержимого на секреты перед публикацией.

Основные проверки разработчика:

```sh
npm run lint
npx tsc --noEmit
node scripts/check-project-estimate.mjs
node scripts/check-callback.mjs
node scripts/check-project-request.mjs
```

Три указанных скрипта проверяют расчёт и формы офлайн, без реальной отправки заявок. Подготовка к основному домену описана в [docs/seo-launch.md](docs/seo-launch.md).
