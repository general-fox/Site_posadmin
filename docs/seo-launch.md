# SEO Posadmin: подготовка и запуск

Основной адрес: **https://posadmin.ru**. Изменения подготовлены в проекте; публикация, настройка DNS и подтверждение аккаунтов поисковых систем выполняются отдельно. Наличие технической оптимизации не гарантирует конкретные позиции: результаты зависят также от конкуренции, полезности материалов, репутации компании и фактической работы сайта после запуска.

## Что реализовано

- 11 индексируемых страниц: главная, компания, каталог услуг, контакты и семь направлений работы. Страницы услуг формируются при сборке: основной текст, ссылки и ответы на вопросы находятся в исходном HTML.
- Уникальные title и description, основной адрес страницы (canonical), Open Graph и Twitter Cards. Карточка ссылки и иконка используют стиль и знак Posadmin.
- Один смысловой H1 на каждой странице. На главной постоянный доступный заголовок сочетается с прежним визуальным переключением слов; копии для анимации скрыты от скринридера. Есть оформление заголовка и меню для отключённого JavaScript.
- Schema.org: Organization, WebSite, Service, BreadcrumbList; на странице контактов — ContactPage и два реальных офиса LocalBusiness. Адреса и телефон берутся из существующих данных сайта. Выдуманные отзывы, рейтинги, координаты, юридические реквизиты и часы работы офисов не добавлены.
- Автоматические `/sitemap.xml` и `/robots.txt`. CSS и JavaScript доступны поисковым роботам. API исключён из обхода и возвращает `X-Robots-Tag: noindex, nofollow`.
- Постоянный редирект `www.posadmin.ru` → `posadmin.ru` с сохранением пути и параметров. Адреса без завершающего слеша; рекламные параметры не попадают в canonical. Несуществующие страницы возвращают HTTP 404 и noindex.
- Переходы из меню, списка специалистов, каталога, связанных услуг и подвала. Нет отдельных копий страниц под каждый город.
- Цены сопровождения и состав базовых модулей связаны с данными калькулятора, города выезда — с общим справочником. Цена выездного модуля явно указана как дополнение к базовому сопровождению.
- Два наиболее тяжёлых изображения свечения первого экрана переведены в WebP: 1 173 308 → 895 218 байт, экономия 278 090 байт. Видимые цветовые каналы и прозрачность сохранены; различия только в RGB полностью прозрачных пикселей.

## Обязательная проверка при публикации

1. Направить `posadmin.ru` и `www.posadmin.ru` на хостинг. Выпустить действующий HTTPS-сертификат для обоих имён. На уровне хостинга включить HTTP → HTTPS; www-редирект уже предусмотрен в приложении. Убедиться, что прокси передаёт исходный Host и нет циклических перенаправлений.
2. Если на домене раньше был другой сайт, выгрузить его реальные адреса из старой карты сайта/аналитики и составить точные 301/308-соответствия. Не перенаправлять все старые страницы на главную: для удалённого материала без замены нужна 404/410.
3. После публикации проверить реальные ответы страниц, canonical, доступность изображений, robots и sitemap. Хостинг не должен добавлять `noindex` или закрывать сайт паролем. Тестовые публичные адреса, наоборот, нужно закрыть от индексации на уровне хостинга.
4. Проверить контакты, адреса, тарифы и рабочий путь заявки. Отправку реальных заявок в Telegram в рамках SEO-проверки не выполняли. Переменные Telegram должны быть настроены на сервере.
5. Проверить мобильную скорость в PageSpeed Insights на опубликованном сайте. Локальная сборка не измеряет реальную сеть, время ответа хостинга и Core Web Vitals посетителей.

## Яндекс и Google после запуска

Подключение этих сервисов бесплатно и не требует покупки рекламы.

1. Добавить сайт в [Яндекс Вебмастер](https://webmaster.yandex.ru/) и [Google Search Console](https://search.google.com/search-console/). Подтвердить владение через DNS либо метатег. Для доменного ресурса Google используется DNS; переменная ниже подходит для проверки ресурса с префиксом URL.
2. Для метатегов задать `YANDEX_SITE_VERIFICATION` и/или `GOOGLE_SITE_VERIFICATION` **до сборки**. Передавать только значение атрибута `content`, не HTML-тег целиком. Примеры имён переменных есть в `.env.example`; после изменения нужна новая сборка и публикация.
3. Отправить `https://posadmin.ru/sitemap.xml`. Проверить главную и страницы услуг инструментами проверки URL, затем запросить индексирование ключевых страниц. Это запрос на обход, а не обещание сроков или позиций.
4. Проверить региональность в Яндекс Вебмастере, заполнить/актуализировать реальные карточки офисов в Яндекс Бизнесе. Телефон, адреса, название и сайт должны совпадать. Не создавать офисы в городах, где есть только выездная команда.
5. По желанию подключить аналитику и цели: заявка, переход в Telegram, клик по телефону, использование калькулятора. Сначала выбрать платформу и правила обработки данных; произвольные счётчики в проект не добавлены.

## Что развивать дальше

- Публиковать подтверждённые кейсы с согласия клиентов: задача, конфигурация, выполненные работы, измеримый результат. Не выдумывать цифры и отзывы.
- Дополнять страницы услуг реальными вопросами из обращений. Разделять новые страницы только при отдельной задаче и достаточном содержании.
- Получать настоящие отзывы и упоминания у клиентов и партнёров. Избегать массовой покупки ссылок, накруток и однотипных страниц с заменой города.
- По данным Вебмастера/Search Console проверять показы, клики, запросы, индексацию и реальные заявки. Исправлять страницы с показами без переходов и развивать направления, которые приводят подходящих клиентов.

## Проверки для разработчика

Сборка: `node node_modules/next/dist/bin/next build`.

Запуск готовой сборки: `node node_modules/next/dist/bin/next start --hostname 127.0.0.1 --port 3101`.

Проверка: `node scripts/check-seo.mjs http://127.0.0.1:3101`.

Скрипт выполняет только чтение: 11 страниц, уникальность метаданных, canonical, SSR H1, JSON-LD, внутренние ссылки и якоря, robots, sitemap, 404, редиректы, noindex API и размеры OG-изображения. Запрос к API — GET, без создания заявки. При добавлении публичных страниц нужно обновить ожидаемое количество в проверке.

## Основания

Подход соответствует рекомендациям [Google для владельцев сайтов](https://developers.google.com/search/docs/fundamentals/seo-starter-guide?hl=ru), [документации Google по данным организаций](https://developers.google.com/search/docs/appearance/structured-data/local-business?hl=ru) и [Яндекса по качеству сайта](https://yandex.ru/support/webmaster/ru/recommendations/intro). Разметка помогает описать содержимое, но не гарантирует расширенное представление в выдаче. FAQ оставлены полезным видимым разделом без обещания специального поискового сниппета.
