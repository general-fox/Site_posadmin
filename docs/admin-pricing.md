# Админка прайса Posadmin

Адрес: `/admin`. Единственный владелец задаётся на сервере через `ADMIN_EMAIL` (сейчас `a230495k@gmail.com`). Вход требует пароль и шестизначный код Google Authenticator. Это самостоятельная учётная запись Posadmin: пароль от Gmail не нужен, почта используется как имя входа. Публичной регистрации и сброса пароля по почте нет.

## Первая настройка на компьютере

1. Использовать Node.js 24.15 или новее в ветке 24, установить зависимости: `npm ci`.
2. Выполнить `npm run admin:prepare`. Команда добавит отсутствующие ключи в `.env.local` и сохранит приватную ссылку в `private-data/admin-setup-link.txt`. Она не задаёт пароль и не создаёт аккаунт. Уже существующие ключи не перезаписываются.
3. Запустить `npm run dev` и самостоятельно открыть ссылку из файла в браузере. Адрес должен совпадать с `ADMIN_ORIGIN` — по умолчанию `http://localhost:3000`.
4. Задать уникальный пароль от 12 символов, отсканировать QR-код приложением Google Authenticator и подтвердить настройку текущим кодом. QR-код создаётся локально сервером, не отправляется сторонним сервисам. На этот шаг даётся 10 минут.
5. Скачать и сохранить резервные коды в менеджере паролей. Каждый код подходит один раз, только вместе с паролем. После настройки удалить `ADMIN_BOOTSTRAP_TOKEN` из окружения и файл с первоначальной ссылкой; перезапустить сервер. Использованный ключ не может создать новый аккаунт даже до его удаления.

Никому не пересылать QR-код, секрет приложения, файл первоначальной ссылки, `.env.local` или резервные коды. Не вводить пароль Google в эту админку. Если выйдете сразу после настройки, для нового входа дождитесь следующего кода: уже принятый код повторно не используется.

## Редактирование цен

В редакторе есть четыре модуля: удалённое сопровождение r_keeper, меню и словари, выездное сопровождение и IT-администрирование. У каждого модуля редактируется формула стоимости в месяц. `N` — количество рабочих мест. Начальные формулы соответствуют ячейкам D5–D8 листа «Тарифы r_keeper 2026» в файле «ТАРИФЫ 2026.xlsx». Все 64 значения для 1–16 мест сверены с файлом. В частности, для r_keeper при 7 и более местах применяется `9500 + (N - 6) * 500`, для IT — `12000 + (N - 6) * 500`. Суммы за 1–6 мест заданы отдельными условиями.

Поддерживаются `IF`/`ЕСЛИ`, арифметика `+`, `-`, `*`, `/`, скобки и сравнения. Аргументы можно разделять запятой или точкой с запятой. Необязательный начальный знак `=` допустим. Ссылки на количество мест из исходной строки Excel, например `D$4`, распознаются как `N`. Остальные ячейки, функции и ссылки на файлы не поддерживаются: это редактор тарифной формулы, а не полный Excel.

Предварительный расчёт позволяет проверить результат до публикации. Перед сохранением сервер проверяет формулу для всех целых количеств от 1 до 10 000 мест: результат должен быть положительной целой суммой, не уменьшаться при добавлении мест и укладываться в установленный предел. Формула разбирается как математическое выражение без исполнения JavaScript или обращения к внешним источникам.

Прайсы, ранее сохранённые в виде отдельных сумм и доплаты, продолжают работать. При открытии они отображаются как эквивалентные формулы; открытие редактора не меняет опубликованные цены. Старые записи истории можно восстановить в новый редактор.

Изменения публикуются только кнопкой «Сохранить цены». До сохранения доступен предварительный расчёт. История показывает последние 50 сохранений и исходный прайс: любую версию можно загрузить в черновик и затем явно сохранить её. Параллельные вкладки не перезаписывают изменения незаметно: устаревшая версия отклоняется.

Один прайс используется в калькуляторах, PDF, серверном расчёте заявок и ценах «от» на страницах услуг. Открытый калькулятор обновляется при возвращении на вкладку и раз в минуту. Если прайс изменился перед скачиванием PDF или отправкой заявки, сервер вернёт актуальные цены и попросит клиента проверить новый расчёт.

## Размещение на Reg.ru

Нужно проверить конкретный тариф: он должен позволять постоянно запускать сервер Node.js 24 и хранить SQLite на постоянном диске. Подходит сервер/VPS с этими возможностями. Обычная загрузка статических файлов по FTP не заменяет сервер приложения. Тариф пользователя пока не подтверждён; публикация и подключение домена не выполнены.

Для боевого сайта задать:

```dotenv
ADMIN_EMAIL=a230495k@gmail.com
ADMIN_ORIGIN=https://posadmin.ru
POSADMIN_DATA_DIR=/var/lib/posadmin
```

`ADMIN_ENCRYPTION_KEY` — секретный ключ в base64 из 32 случайных байт. `ADMIN_BOOTSTRAP_TOKEN` — ключ первой настройки (64 hex-символа); оба создаёт `admin:prepare`, если они ещё не заданы. Подготовку на сервере запускать с `NODE_ENV=production`, после настройки перезапустить процесс приложения. На продакшене админка откажет в работе без HTTPS-адреса, ключа и абсолютного пути к данным.

Папка данных должна принадлежать пользователю приложения (права 700, файлы 600), находиться вне `public`, каталога сборки и заменяемого каталога релиза. Не раздавать её через Nginx/Apache. Обновления приложения не должны удалять эту папку или генерировать новый ключ шифрования. Внешний доступ — только через HTTPS; порт Node.js оставить на loopback за обратным прокси. Запускать один экземпляр приложения; SQLite рассчитана на один сервер с локальным диском, не на несколько контейнеров с независимыми файловыми системами.

Резервировать базу SQLite штатным online-backup SQLite либо при остановленном приложении. В режиме WAL простое копирование одного файла работающей базы небезопасно. Ключ шифрования сохранить отдельно в защищённой резервной копии: без него секрет Authenticator восстановить нельзя. Проверить восстановление резервной копии до запуска.

Если потеряны Authenticator и все резервные коды либо пароль, восстановление требует доверенного администратора сервера и проверки владельца. Не удалять базу и не включать публичный обход авторизации: вместе с базой пропадёт история и изменённый прайс. До разработки отдельной процедуры восстановления использовать менеджер паролей и резервные коды.

## Защита и ограничения

Пароль хранится как scrypt-хеш с индивидуальной солью; секрет Authenticator зашифрован AES-256-GCM отдельным серверным ключом. Коды проверяет OTPAuth; повторное использование и гонки блокируются транзакцией SQLite. Сессия — случайный непрозрачный токен (в базе только хеш), HttpOnly/SameSite=Strict cookie и Secure на HTTPS. Сессия истекает через 8 часов или 30 минут бездействия; выход отзывает её на сервере.

Все операции с ценами проверяют сессию на сервере. Изменяющие запросы принимаются только с `ADMIN_ORIGIN` и с ограниченным JSON-телом. Общий лимит — 60 запросов входа в минуту; лимит второго фактора — 10 попыток за 15 минут только после правильного пароля. Ограничения сохраняются после перезапуска и не обходятся подменой IP. Одновременно выполняются не более четырёх проверок пароля, без накопления очереди. Общий лимит может временно блокировать вход при целевой атаке; на внешнем прокси желательно дополнительное ограничение запросов. HTTP-заголовки закрывают встраивание админки во фрейм и кеширование её API. Админка исключена из индексации, но это не заменяет авторизацию.

Пароль и TOTP защищают от многих распространённых атак, но TOTP не защищает от фишинга в реальном времени. Безопасность также зависит от обновлений сервера, TLS, защиты компьютера/телефона и резервных копий. Гарантии полной неуязвимости нет.

Проверки: `node scripts/check-pricing.mjs`, `node scripts/check-pricing-formula.mjs`, `node scripts/check-pricing-integration.mjs`, `node scripts/check-admin-security.mjs`, `node scripts/check-callback.mjs`, `node scripts/check-project-request.mjs`, `npm run build`.
