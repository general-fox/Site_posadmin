# Обратные звонки: выбор специалиста и Telegram

Форма «Запросить звонок» передаёт в `POST /api/callback` телефон, согласие на обработку персональных данных и `specialist`: `manager` или `technical`. Быстрый запрос использует `contactSoon: true`, пустые `date` и `time`. Техническое направление в сообщении обозначено как «технический специалист (r_keeper)» и «Перезвонить по готовности специалиста», без обещания срока реакции.

Старые формы без `specialist` по-прежнему обращаются к менеджеру. Невалидное значение возвращает 400 до отправки. Выбор даты/времени и проверка расчёта тарифа сохраняются.

## До подключения сервисного чата

Пока `TELEGRAM_SERVICE_CHAT_ID` пуст, оба направления отправляются в существующий `TELEGRAM_ADMIN_CHAT_ID` с явной строкой «Специалист». Сохраняется прежний fallback: `BOT_TOKEN` / `ADMIN_CHAT_ID`, затем локальный `bot/.env` для недостающих значений. Разделения по темам в этом режиме нет.

## После добавления бота

1. Добавьте бота в нужную сервисную супергруппу, включите темы и разрешите ему отправлять сообщения в нужные темы.
2. Укажите `TELEGRAM_BOT_TOKEN` и `TELEGRAM_SERVICE_CHAT_ID` этой группы в окружении сервера.
3. Укажите ID темы менеджера в `TELEGRAM_MANAGER_TOPIC_ID`, ID темы r_keeper — в `TELEGRAM_RKEEPER_TOPIC_ID`. Нужен именно `message_thread_id`, положительное безопасное целое число, а не ссылка на тему.
4. Перезапустите приложение с новым окружением и отдельно проверьте каждое направление согласованной тестовой заявкой.

Если сервисный чат задан, запрос менеджеру уходит только в тему менеджера, техническому специалисту — только в тему r_keeper. Отсутствующий/некорректный ID нужной темы возвращает 503 без отправки. Ошибка Telegram возвращает 502. Запрос не перенаправляется автоматически в другую тему или старый административный чат. Неудачная заявка не сохраняется в очередь: пользователь получает предложение повторить отправку.

Этот маршрутизатор относится только к обратным звонкам, включая звонки по расчёту тарифа. Заявки на запуск проекта из `/api/project-request` сохраняют прежний административный адресат.

Секреты, телефон и ответ Telegram не записываются в диагностические сообщения endpoint. Настройка реального бота/чатов и отправка тестового сообщения не выполняются автоматически.

## Офлайн-проверка

`node scripts/check-callback.mjs` проверяет оба направления, старые формы, fallback, ошибки конфигурации и доставки, планирование и расчёты. Окружение, чтение файлов учётных данных и `fetch` подменены; реальные секреты не читаются, сетевых запросов нет.
